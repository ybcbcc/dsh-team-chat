上下文界面怎么看

用它回答三个问题：成员这一步收到了什么材料，输入为什么增加，以及结论背后有哪些操作记录。

插件完整介绍与使用手册适用：DSH 面板及插件浏览器入口 · 2026-11-15

图 1—4 来自已有场景的真实运行记录。图 5—7 为实际界面加载的预设教学数据，未保存到你的场景，也未调用模型、读写示例文件或执行示例命令。截图可点击放大。

1. 第一次打开，先按这条路线看

  1. 在场景协作工作区顶部点击上下文。也可以从对话右侧的成员框点击查看实际采用的上下文，直接按该成员筛选。
  2. 第一次建议在右上角成员中选择 Codex 或 DeepSeek，先看一位成员的记录。
  3. 先看记录范围，确认当前保存的是原生请求还是阶段快照。
  4. 在上下文浏览器顶部选择需要查看的步骤，再展开分类和具体条目。
选成员→看记录范围→选请求步骤→展开输入材料→核对输出与来源
先区分上下文与记忆。

上下文是某次请求交给成员的材料，可能包含任务、记忆、技能、历史和协作者结果。记忆是场景里长期保存、供后续任务选用的知识。保存了记忆，不代表每次请求都会采用它。

2. 界面各区怎么看

区域回答什么问题怎么读
1 成员与刷新现在看谁的记录？“全部成员”汇总团队；选某位成员后查看其记录。任务运行时会自动更新，需要时可点“刷新”。
2 上下文统计当前范围有多少任务和请求？图中是 2 轮任务、12 条请求 / 阶段记录。一次任务可有独立处理、交叉验证、汇总等多个阶段，12 不代表你发了 12 次问题。
3 记录范围这些记录详细到什么程度？图中原生请求 0、阶段快照 12、用量上报 12 / 12：保存了阶段输入及用量，不能据此看到每一次内部模型请求的完整输入。
4 Token 统计输入和输出用了多少，输入由哪些类别组成？分类与用量采用不同口径，具体见下一节。
5 耗时统计成员与工具花了多少时间？按成员累计，并行部分会分别计入；它不等于你实际等待的时长。
6 当前上下文当前筛选范围内，最新一条输入有多大？优先显示上报输入用量；没有上报时显示带“≈”的估算。容量未上报时无法计算窗口占用。
7 上下文浏览器我选中的这一步具体收到了什么？选择步骤，展开分类和条目；可查正文、来源、版本以及该阶段的输出。
8 上下文趋势输入在哪一步增长或缩小？每根柱子对应一条记录。点击柱子，会切换浏览器中的请求；切换“增量”便于找变化。
“当前上下文”和“选中的上下文”可能不同。

左侧“当前上下文”始终显示当前成员筛选范围内的最新记录。右侧浏览器和趋势下方的步骤摘要跟随你选择的记录。点击历史柱形后，左侧最新值不跟着变，这是两块卡片的不同用途。

3. Token 和耗时，哪些数字可以放在一起比较

Token 是模型处理文本等材料时使用的计量单位。这里主要用来判断输入大小和变化，不能直接换算成固定的汉字数。

界面标记含义读图 1 的例子
≈ 或“估算”插件依据保存的文字估算大小，用来比较材料的类别和相对体积。注入上下文累计约 10.6k，占已保存输入类别估算的 64.8%。
“上报”及输入 / 输出运行时返回的用量，包含其实际统计范围中的输入或输出。输入 173,837，输出 10,793；相加为 184,630，圆环中央显示 184.6k。
缓存与缓存命中上报输入中有多少来自缓存读取。缓存是输入的一部分。缓存 79,744，约为输入的 45.9%；不要再把它加到输入总量上。
— / 未上报没有可用数据。“已计时 0 / 12”表示这 12 条历史记录没有可显示的耗时，不表示全部瞬间完成。
窗口占用最新输入量与已上报窗口容量的比例。当前场景显示“窗口容量未上报”，因此不显示百分比，也不代表窗口已满。

圆环颜色与中央总数不是同一套数值。颜色反映保存输入的分类估算；中央“上报总量”是输入加输出的运行时用量。两者可以不同，尤其是只有阶段快照、缺少引擎额外注入内容时。多次请求重复携带同一段材料，也会多次计入累计统计。

耗时也不要重复相加。“成员累计耗时”分别累加成员的请求 / 阶段时间；工具时间可能已包含其中。两位成员各执行 30 秒且同时开始，成员累计可能是 60 秒，用户实际等待约 30 秒。

当前没有可核对的模型报价，因此这里不提供费用结算。分类估算、输入输出用量和费用是不同概念。

4. 例子一：确认 Codex 有没有收到 DeepSeek 的意见

  1. 右上角“成员”选择 Codex。
  2. 在浏览器的步骤下拉框选择交叉验证 1；也可以点击趋势中对应的柱子。
  3. 展开注入上下文，再展开一条成员初步结果。
  4. 打开条目底部的来源与版本，核对来源成员。

你能确认：这条 DeepSeek 结果被列入了 Codex 该阶段的输入材料。它不能单独证明 Codex 已正确理解或采纳意见；还应展开底部本次请求 / 阶段的输出核对回应。

七类材料分别是什么

分类常见内容适合检查什么
系统提示词成员角色、协作规则、阶段要求；原生记录中也可能有引擎系统提示。是否分配了正确职责和行为要求。
工具定义工具名称、用途、参数说明和必填项。记录中向模型提供了哪些工具接口；有定义不等于实际调用过。
用户消息本轮任务、近期主聊天、附件路径等保存的用户侧材料。要求或附件路径是否进入了这一步。
注入上下文场景概况、被采用的记忆、成员交接结果，以及可观测到的压缩摘要等。团队是否拿到了需要的背景和协作意见。
技能注入本次实际纳入的技能材料。期待的技能说明是否随阶段输入保存。
助手消息该请求之前已保存、并进入其输入的助手回复。模型接续时带了哪些助手历史。
工具结果该请求之前产生、并进入其输入的工具返回内容。文件正文、搜索结果或命令输出是否进入了后续请求。

浏览器里的常用按钮

  • 搜索：匹配当前选中请求的条目名称、正文和来源。普通分类模式下，搜完还要展开相应分类；它不搜索整个场景的所有历史请求。
  • 大小 / 名称 / 顺序：在普通分类模式下调整分类内的条目顺序。先按“大小”找最占空间的条目；按“顺序”恢复保存顺序。
  • 原文 / 格式化：原文适合核对完整文字；格式化适合阅读。工具定义若能解析，会显示参数、类型和必填项。
  • 复制：复制该条保存的正文。原文如果已被截取，复制的也是保留部分。
  • 本次请求 / 阶段的输出：显示输入之后产生的回复和关联工具结果。不要把它与七类输入中的“助手消息”“工具结果”混在一起。

5. 例子二：为什么到了交叉验证，上下文突然变长

沿用图 2 的 Codex 记录，先选“独立处理”，再选“交叉验证 1”。交叉验证会携带成员的初步结果，输入增长可能来自协作材料。

  1. 在上下文趋势切到步骤和增量，点击需要追查的柱子。
  2. 在浏览器切到新增，先看本次新出现或发生变化的条目。
  3. 展开增量较大的分类，核对增加的内容；需要查看前后完整输入时，切回完整。
开关具体含义
步骤 / 轮次“步骤”显示每条保留的请求或阶段快照；“轮次”只显示每位成员在该任务轮次中的最后一条输入，不是整轮累计求和。
总量 / 增量“总量”显示保存输入的分类估算；“增量”按类别与同一成员的上一条保留请求比较。没有上一条时，以零为基线。比较可能跨任务轮次。
总览把更多柱子压缩进同一视野，适合观察整体走势；再次点击恢复普通宽度。
完整 / 新增“完整”显示本次保存的全部条目；“新增”只显示相对该成员上一请求，类别、名称或正文组合不同的条目。修改过的条目会整条显示；这里不是逐字差异，也不单列删除内容。

柱子下降不一定是压缩。可能是阶段更换、交接材料减少，或输入组织发生变化。要判断是否压缩，继续看“上下文事件”里有没有相应记录；没有事件时，仅凭下降不能确定原因。

6. DNA 模式：按输入保存顺序读一遍

在浏览器右上角点击DNA 模式。普通视图按七类材料分组；DNA 视图把条目按该请求保存的输入顺序展开为一条序列。

适合用来检查：职责、任务、交接内容是否被放进同一份输入，以及各条保存材料的先后位置。它展示的是输入排列，不展示模型内部思考顺序或注意力权重。

DNA 模式按保存顺序显示，不使用“大小 / 名称”的排序；如果启用了搜索或“新增”，列表会只显示符合条件的条目。

7. 例子三：确认“清理前先问我”这条记忆有没有采用

假设你的场景里保存了一条记忆：“所有清理先给清单，未经确认不删除。”下面用隔离教学样例演示核对方法。

  1. 选择目标成员和对应请求步骤，展开注入上下文。
  2. 找到该记忆的标题；也可以搜索“清理前先确认”等关键字。
  3. 展开条目，核对正文和采用原因。
  4. 展开来源与版本，确认来源为记忆并查看修订号；有查看来源时，可跳转到记忆页。

你能确认：该次输入包含了这条规则的这个版本。之后把记忆改成 v3，过去请求中保存的 v2 仍然保留，便于追查当时依据。

如果没有找到，先确认成员、步骤和记录范围，再到记忆页核对条目是否参与采用。记忆会按状态、关联程度和预算选用，不会把所有知识无条件塞入每次请求。原生请求的来源也可能只记录到运行时消息，此时可以搜索正文，结合阶段快照核对。

要纠正过时知识，请到记忆页编辑或停止采用，下一次请求再检查结果。上下文页用来查看已保存的输入记录，没有直接删除某段历史输入或强制压缩当前成员上下文的按钮。

8. 例子四：确认读写了什么，以及命令为什么失败

页面下方有上下文事件、文件活动和命令执行。这些卡片用来从结果反查记录。

查文件

  1. 在“文件活动”按路径搜索，或选择读取 / 写入 / 搜索 / 图片。
  2. 展开文件，核对完整路径、成员、时间和操作状态。同一个文件有多种操作时，会归入多个筛选类别。
  3. 点击定位结果，回到关联请求的输出区域核对详情。

“+3”表示记录中识别到新增 3 行。只有工具提供可识别的差异信息时，才有相应行数；没有行数不代表没有修改。文件列表来自可识别的工具记录，不是电脑上所有文件操作的完整监控。

查命令

  1. 选择错误筛选，或搜索命令、程序名称。点击左侧“程序分布”中的程序也可以筛选。
  2. 展开记录，查看完整命令、成员、工作目录、耗时、退出码。
  3. 点击读取命令输出查看保留输出；若已加载，会直接显示正文。运行中的命令需等结束后读取。
  4. 点击定位请求，回到相关步骤，看这次结果如何影响后续回答。

图 7 应该得出什么结论

空间查询这条命令被记录为完成，退出码为 0；路径查询这条被记录为错误，退出码为 1，输出说明找不到示例路径。此时应该核对路径，不能宣称这一路径已成功检查或清理。

单条命令成功也不等于整个任务已完成。仍需对照主聊天中的交付结果，以及任务要求的检查项。

查上下文事件

按注入、请求、压缩、清理、切换、模式、交接、用量等类型筛选，或搜索事件、成员。只有已有记录的类型才会显示。展开事件查看细节，存在“定位请求”时可跳到关联输入。“清理”在这里指上下文材料的清理事件，不能据此判断磁盘文件被删除。

9. 常见问题与速查

为什么 Codex 和 DeepSeek 显示的材料详略不同？

Codex 当前主要显示插件组装的阶段输入、实际工具活动及上报用量。DSH 原生请求还可以通过会话事件记录系统提示词、工具定义和消息。先看“记录范围”和单条输入下方的范围说明；已有旧任务不会自动补出未曾记录的内部内容。

为什么分类是 0，或者某些卡片没有内容？

可能是该步骤没有这类材料，也可能当前记录范围没有覆盖。例如图 1 的旧阶段记录没有工具定义，不能据此断言成员当时没有任何工具。文件或命令没有可识别记录时，也会显示为空。

我选了一个步骤，为什么上面的统计没变？

统计卡片汇总当前成员筛选与当前加载页的记录；步骤选择主要联动浏览器和趋势摘要。要看单步输入用量，请看浏览器顶部“估算 / 上报”和趋势下方的步骤摘要。

怎么查看更早的任务？

滚到页面底部；如果出现“查看更早记录”，点击进入更早的一页。当前一页最多读取 600 个输入快照、2,000 次工具记录、400 条上下文事件和 400 个文件。页内累计数字不是整个场景永远完整的总账。

界面是否保证保存了模型看到的每个字？

以每条记录的范围说明为准。原生采集最多保留 1,000 个输入条目，单条正文最多 10 万字符；超限时会标记截取或范围近似。阶段快照和原生请求也有不同覆盖范围。输入记录展示材料，不证明模型一定正确理解了其中内容。

怎么在这里管理或减少上下文？

先用趋势和浏览器找出重复、过时或过大的材料，再到“记忆”页修订相关知识，或到“团队”页调整角色和技能，随后核对新任务的输入。当前上下文页以查看和追溯为主，不能在这里直接改写历史请求或手动强制压缩成员上下文。
